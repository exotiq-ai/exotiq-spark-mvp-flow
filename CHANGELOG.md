# Changelog

One line per shipped change, newest first: date (UTC) — what changed — why.

- 2026-11-25 — Published to app.exotiq.ai: main 4df2be07 (#65–#67) — the production front end was still on the 11-19 build.
- 2026-11-25 — No more invented hero images (#67): Add Vehicle no longer generates an AI picture from make, model and colour, the empty Photos card offers only Upload Photos, and the `generate-hero-image` edge function is removed from the repository and deleted from production — the generated image showed a car that was not the operator's as if it were the real one.
- 2026-11-25 — Customer import recognises HQ Rental Software's customer export (or pick it under "Where is this file from?") and imports it in one step: one customer per email, other people on a shared email kept in notes, rows without email listed for the operator, every customer tagged "HQ import"; customer import now requires an email — operators switching from HQ can bring their customers over, and a phone-only row no longer fails a whole insert batch.
- 2026-11-19 — Demo fleet refresh fixes (migration 20261119030000): missing states are reported instead of crashing the run, and when no returned rental is left owing it raises post-rental charges on the latest one — on production the refresh failed with "malformed array literal" once settling the old overdue payments left nothing owing.
- 2026-11-19 — The fleet loads every booking (last 90 days) and every payment, a page at a time; the demo refresh dates its payment rows when the rental ended and keeps only recent overdue payments (migration 20261119020000) — Supabase returns at most 1,000 rows per request, so teams past 1,000 payments or bookings silently lost the rest (on the demo team, every real payment and the overdue ones disappeared from Pulse).
- 2026-11-19 — `supabase/snippets/backfill_demo_refresh_payouts.sql` logs the partner payouts a first-version demo refresh created, so its undo removes them too — the production demo refresh ran before the partner-payout fix was applied.
- 2026-11-19 — Demo fleet refresh handles partner payouts (migration 20261119010000): payouts the booking trigger creates are logged for undo, payouts for rentals returned over 14 days ago are marked paid as demo records (no transfer), and the undo no longer re-writes unchanged booking statuses — completing rentals on partner cars created pending payouts the undo could not remove, and re-writing a completed status created new ones.
- 2026-11-19 — Demo fleet refresh: `public.refresh_demo_fleet()` (migration 20261119000000) brings the demo team up to date on demand — past rentals completed and paid with demo payment rows (no Stripe), current rentals active, and a few of each alert kept (late returns, pickup today, return due, overdue payment and task, overdue and blocked work order, maintenance due, expiring customer and Vault documents, a mileage-tracked rental); every change is logged for undo — nothing finishes a booking on its own, so the demo showed 630 overdue returns.
- 2026-11-18 — The production Netlify site now holds the public Supabase project id, URL and publishable key for every deploy context, so a Netlify build points at production on its own — they were missing, and a build made with Netlify's tools came out with no backend address.
- 2026-11-18 — Published to app.exotiq.ai: Fleet → Pricing with mileage, rates, deposits and team defaults (#57–#59), after migrations 20261116000000 (unlimited miles) and 20261116010000 (team gas fee) were applied to production; checked live: car edit with the Unlimited switch, the Pricing table save, and a new booking (flag copied onto it) — the production front end was still on the 11-14 build.
- 2026-11-16 — Team defaults (minimum rental rate, default deposit, gas / re-fuelling fee) are set once for the team in Fleet → Pricing; the gas fee now lives on the team (migration 20261116010000, backfilled from each owner's saved values) and the minimum rate is saved where pricing reads it — the old Settings field saved the minimum rate to the signed-in person's own settings, where nothing read it, and each staff member could have a different gas fee.
- 2026-11-16 — Rate tiers (daily, 3-hour, 6-hour, multi-day) and each car's deposit hold moved from MotorIQ to Fleet → Pricing as one table beside mileage; the "% of daily" rule fills rows for review instead of saving at once; the minimum rate applies only to rates being changed — pricing was split across MotorIQ and Settings.
- 2026-11-16 — Fleet → Pricing (new tab): team mileage default plus every car's miles/day, per-mile rate and an Unlimited switch in one table; managers edit cars, only the team owner edits team defaults (as the database already enforces); unlimited cars are never charged overage (flag copied onto each booking by a trigger; migration 20261116000000) — operators had to open each car to set mileage and could not offer unlimited miles.
- 2026-11-16 — Tablets start with the sidebar collapsed and show the header search from 1024 px; Fleet header buttons wrap on phones; vehicle menus have 40 px touch targets and names; Bookings tabs read Overview/Calendar/Payments; the phone header names the Fleet page — at 768 px the header overlapped itself, Import was cut off, and Fleet was labelled "Dashboard".
- 2026-11-16 — Dashboard shows content in ~2 s instead of ~7.4 s on a revisit (Home tab: 0.8 s instead of 9.3 s): MotorIQ time-zone helpers reuse one formatter per zone, customer notes no longer hold the dashboard on loading, the signed-in user keeps one identity, role and profile are shared lookups, the subscription check runs once per user — the overview rebuilt an Intl formatter for every day of every booking and loaded its data twice.
- 2026-11-16 — Mileage overage: included miles = miles/day × days (booked, or kept when late), shown with the working at check-in and in Record Payment; overage rate is a free $X.XX field; no invented 250 mi / $1.50 / $0.50 fallbacks — check-in compared a whole trip to one day's allowance and overcharged multi-day rentals.
- 2026-11-16 — `.env` is no longer tracked; `.env.example` shows the variables and CI uses placeholders — the tracked file still named the retired Lovable backend, while production takes its values from Netlify.
- 2026-11-14 — Super Admin: a marketplace request whose platform fee is not confirmed shows "Confirm fee to approve"; errors show their real message (`describeError`) — approvals failed with "[object Object]".
- 2026-11-13 — Payment totals count only the operator's own payments; the Exotiq charge is shown on its own line; Stripe Checkout notes the separate EXOTIQ RENT charge — a $2 rental showed a negative balance.
- 2026-11-13 — Add Vehicle accepts a blank Year; signed-in users can delete vehicle-photo files again — save refused a blank year; replaced photos left files behind.
- 2026-11-13 — Backend moved from Lovable Cloud to the owned Supabase project; Command Center hosted on Netlify.
